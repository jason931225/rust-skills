# type-affine-quantity

> Split an absolute quantity from its delta: implement `Sub<Self> -> Delta` but never `Add<Self> -> Self`, so adding two points does not compile

## Why It Matters

A temperature, a timestamp, a position, and a calendar date are all *points*
in an affine space, not vectors: two of them can be subtracted to get a
meaningful difference (`Instant - Instant = Duration`, `100°C - 20°C = 80°`),
but adding two of them together produces a number with no physical meaning
(`Instant + Instant`, `100°C + 20°C`). A newtype that wraps the value and
derives or hand-implements `Add<Self, Output = Self>` for convenience makes
`Celsius(100) + Celsius(20)` compile to `Celsius(120)` — a value the newtype
correctly range-checks and correctly labels, and that is still nonsense. Unit
wrapping (`Celsius` vs `Fahrenheit`, `Meters` vs `Feet`) catches the wrong
*unit*; it does not catch the wrong *operation*, because same-unit addition
of two absolute quantities looks identical in the type system to the
legitimate case of adding a quantity to a compatible displacement.

## Point And Delta Operator Rules

- Model an absolute quantity (a point) and its difference (a delta,
  displacement, or duration) as two distinct types, even when they share a
  representation and a unit.
- Implement `Sub<Self> -> Delta` on the point type, `Add<Delta> -> Self` and
  `Sub<Delta> -> Self` on the point type, and ordinary vector-space
  arithmetic (`Add`, `Sub`, scalar `Mul`) on the delta type. Do not implement
  `Add<Self, Output = Self>` on the point type — there is no legitimate
  result for adding two points.
- Apply this to every point-like quantity: timestamps and durations,
  absolute temperatures and temperature changes, positions and
  displacements, calendar dates and day-counts, absolute pressures and
  pressure deltas.
- Where a delta genuinely needs a different valid range than its point type
  (a temperature delta can be negative even when the point type cannot),
  give it its own validation rather than reusing the point type's
  constructor.
- When a derive or macro generates arithmetic operators for a family of
  newtypes, generate delta-aware operators for point types explicitly rather
  than defaulting every quantity to `Add<Self>`.

## Bad

```rust
use std::ops::Add;

#[derive(Debug, Clone, Copy, PartialEq)]
struct Celsius(f64);

// Compiles, range-checks correctly, and is still physically meaningless:
// 100°C + 20°C is not 120°C of anything.
impl Add for Celsius {
    type Output = Celsius;
    fn add(self, rhs: Celsius) -> Celsius {
        Celsius(self.0 + rhs.0)
    }
}
```

## Good

```rust
use std::ops::{Add, Sub};

/// An absolute temperature: a point, not a vector.
#[derive(Debug, Clone, Copy, PartialEq, PartialOrd)]
struct Celsius(f64);

/// A temperature change: the vector space Celsius points live in.
#[derive(Debug, Clone, Copy, PartialEq, PartialOrd)]
struct CelsiusDelta(f64);

impl Sub for Celsius {
    type Output = CelsiusDelta;
    fn sub(self, rhs: Celsius) -> CelsiusDelta {
        CelsiusDelta(self.0 - rhs.0)
    }
}

impl Add<CelsiusDelta> for Celsius {
    type Output = Celsius;
    fn add(self, delta: CelsiusDelta) -> Celsius {
        Celsius(self.0 + delta.0)
    }
}

impl Add for CelsiusDelta {
    type Output = CelsiusDelta;
    fn add(self, rhs: CelsiusDelta) -> CelsiusDelta {
        CelsiusDelta(self.0 + rhs.0)
    }
}

fn main() {
    let boiling = Celsius(100.0);
    let room = Celsius(20.0);

    let change: CelsiusDelta = boiling - room;
    assert_eq!(change, CelsiusDelta(80.0));

    let warmed: Celsius = room + CelsiusDelta(15.0);
    assert_eq!(warmed, Celsius(35.0));

    // `boiling + room` does not compile: `Celsius: Add<Celsius>` does not
    // exist. Only the delta type composes with itself.
    let total_change = CelsiusDelta(10.0) + CelsiusDelta(5.0);
    assert_eq!(total_change, CelsiusDelta(15.0));
}
```

## Arithmetic Cases To Test

- subtracting two points produces a delta with the physically correct sign
  and magnitude;
- adding a delta to a point produces a point, and the reverse (point plus
  point) is not expressible — confirmed by the absence of an `Add<Self>` impl
  on the point type, not by a runtime check;
- two deltas add together to produce a delta, matching ordinary vector-space
  arithmetic;
- a family of point/delta types generated by one macro or derive each get
  the point-vs-vector split individually, not a blanket `Add<Self>`.
